# Анализ процедурного кода

## Задание 1.1. Таблица анализа

| Что | Где в исходном коде | Куда перенести |
|---|---|---|
| Секретное число `secret` | `secret = random.randint(1, 100)` | `Game._secret` |
| Предел попыток `max_attempts` | локальная переменная `max_attempts = 10` | `Game._max_attempts` |
| Текущее число попыток `attempts` | локальная переменная цикла | `Player._attempts` |
| Генерация числа | `random.randint(...)` | `Game.run()` |
| Проверка попытки (`Больше/Меньше/Угадали`) | ветвление `if guess < secret ...` | `Game.check_guess()` |
| Игровой цикл `while attempts < max_attempts` | тело функции | `Game.run()` |
| Имя игрока | отсутствует (хардкод «Игрок») | `Player._name` |
| Ввод данных | `int(input("Ваш вариант: "))` | `UI.get_input()` |
| Вывод данных | все вызовы `print(...)` | `UI.show_message()` |
| Обработка неверного ввода | `try / except ValueError` | `Player.make_guess()` |

## Задание 1.2. Письменные ответы

1. **Какие классы выделены и почему.**
   - `Game` — игровой цикл, генерация секрета, проверка попытки. Отвечает за правила игры.
   - `Player` — состояние игрока (имя, счётчик попыток) и получение хода.
   - `UI` — ввод/вывод, вынесенный отдельно, чтобы логику можно было тестировать без ручного ввода.
   Каждый класс описывается одним предложением без союза «и» — признак единственной ответственности.

2. **Какие атрибуты приватные и почему.**
   Все: `Game._secret`, `Game._max_attempts`, `Game._ui`, `Player._name`, `Player._attempts`, `Player._ui`.
   Приватность защищает инварианты: снаружи нельзя присвоить отрицательное число попыток или подменить секрет в обход правил. Доступ — через свойства (например, `secret` только для чтения).

3. **Какие методы публичные и почему.**
   - `Game.run()`, `Game.check_guess()`, свойство `Game.secret` — контракт игры.
   - `Player.make_guess()`, `Player.increment_attempts()`, свойства `name`, `attempts` — контракт игрока.
   - `UI.show_message()`, `UI.get_input()` — контракт интерфейса.
   Публично только то, что составляет API класса; детали реализации скрыты.

4. **Есть ли «God Object»?**
   В исходном коде — да, де-факто. Вся игра живёт в одной функции и использует общие переменные `secret` / `attempts`; функция одновременно отвечает за правила, ввод-вывод и игровой цикл. Признаки: смешение ответственностей, опора на общее состояние, невозможность переиспользовать части по отдельности. После рефакторинга ответственности распределены по трём классам.
